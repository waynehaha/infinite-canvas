# 待测试

## 上游通用修复

- Images 与 Responses 接口开启流式返回时，可从完整事件或分片事件中正确提取最终图片；上游错误会正常显示，不会误报为缺少图片。
- 画布链式生成、局部编辑、视角变换和全景图生成使用稳定的素材文件名，节点标题包含中文、空格或特殊字符时不再破坏请求。
- 通用 APIMart/KIE 渠道可正确转换 MiniMax-H3 的 768P、2K 分辨率，并保留 `2K`、`4K` 一类视频清晰度写法。

## 用户诊断日志导出

- 视频创作台诊断日志新增用户原始参数、归一化配置、模型能力快照、最终请求一致性检查和真实输出尺寸记录；AIHub Omni 旧尺寸值会正确转换为 `9:16` / `16:9`。

- 画布按每次生成提交建立独立诊断任务，并以画布作为归属；批量请求、手动重试和刷新后的任务轮询会继续记录对应步骤。
- 图片与视频任务会记录配置检查、参考素材数量和格式、实际请求字段概况、任务 ID、关键进度、结果获取及写入画布状态。
- 请求日志保留最终请求体的嵌套结构及模型、尺寸、质量、时长、数量等安全参数值，并固定导出经过密钥扫描的提示词正文及其字符数、UTF-8 字节数。
- 每个参考图和参考视频记录尺寸、字节数、格式、来源及是否进入实际请求；本地参考图和参考视频会以原文件加入 ZIP，公网参考素材只保留隐藏鉴权参数后的链接。
- 本地 MP4/MOV 参考视频会在后台线程分块读取轨道信息，诊断日志记录平均、最低、最高 FPS、恒定/可变帧率、总帧数和解析状态；解析失败不会阻止正常提交。
- 画布顶部新增独立“日志”入口；打开后自动读取当前画布的最新提交，可导出 ZIP 诊断包或清空当前画布最近 7 天的本地诊断记录；日志入口不作异常告警，不显示状态红点。
- 生图工作台的“全部结果”和视频创作台的“全部成果”标题旁新增局部“日志”入口，只显示对应工作台的提交；一次批量生成共用一条诊断提交，子任务创建、轮询、成功和失败会持续写入同一日志。
- AIHub 本地参考素材上传会分别记录素材读取、上传授权、文件直传和完成确认；网络异常会标明具体失败阶段，并保留素材类型、序号、大小、格式、耗时和 HTTP 状态，不记录临时上传地址或鉴权信息。
- 视频创作台提交失败后会保留诊断任务关联并正确结束为失败状态，不再长期显示“进行中”。
- 生图记录显示成功但图片无法读取或展示时改为标记“异常”，并写入结果保存/展示阶段；日志功能接入前的异常记录会生成明确标注且不冒充完整请求链路的“历史补充”日志。
- 首次导出会明确提示诊断包包含提示词正文、本地参考图和参考视频原文件，“下次不再提醒”默认勾选且仅在成功导出后记忆。软件配置中的 API Key、登录凭证、Cookie 和请求鉴权信息不会额外写入；参考图和参考视频的画面、声音、原文件名及媒体元数据保持原样。
- 安全说明仅用黄色强调图标和标题，容器、边框及说明文字统一使用黑白灰中性色。

## AIHub 默认渠道

- Seedream 4.5/5.0/5.0 Pro 的文生图、单参考图和多参考图统一使用 `/images/generations` JSON 协议；本地渠道和登录后云端任务使用相同请求结构。
- `gpt-image-2` 图生图恢复为合法 multipart 文件上传，最多 6 张、参考图合计不超过 5MB；不再把临时图片网址作为 JSON 发送到 `/images/edits`。
- Gemini 图片请求不再发送文档未公开的生成数量和质量字段，并恢复方形、横屏、竖屏方向选择。
- 38 个 AIHub 媒体模型全部绑定明确请求协议；在线配置构建会拦截无协议模型、Seedream 错误端点、GPT Image 2 错误素材限制和 Gemini 未公开字段。
- AIHub 模型目录改为在线自动更新：软件先使用本地缓存启动，再从 `aihubcc-config.pages.dev` 静默检查最新配置；断网、校验失败或配置协议过新时继续使用上一次正常配置。
- 设置页新增“AIHub 模型中心”，支持分类、搜索、模型能力摘要、文档入口和“立即检查”；用户不需要手动导入配置文件。
- 在线配置使用版本化文件和 SHA-256 校验，固定入口只允许指向受信任的配置站，远程内容不能下发代码或改变 AIHub API 地址。
- 在线配置协议升级为第 3 版，可声明受限制的请求字段映射、类型转换、条件字段、素材依赖、同步响应、异步状态、真实进度、结果下载、错误提示和计费说明；远程配置不能下发脚本、任意请求头、外部接口地址或密钥。
- 填写 AIHub Key 后，软件会用不计费的模型列表接口筛选该 Key 实际可见的模型；其他自定义渠道不受影响。
- 测试结果会区分 Key 无效、权限不足、模型接口不存在、网络异常和服务端异常；修改 Base URL 或 Key 后会清除旧测试状态。
- 新用户默认提供 `AIHub` 渠道，当前在线目录包含普通 Key 可见的 44 个模型；不预置 4 个编程或通用文本 GPT 模型。
- 模型按文本、图片、视频和音乐分类，默认分别使用 `gemini-3-flash`、`gpt-image-2`、`omni-fast` 和 `gemini-music`。
- GPT Image 同步生图、multipart 图片编辑及异步 1K/2K/3.5K/4K 生图已按模型协议区分。
- `gpt-image-2` 已按真实调用结果增加 4:3、3:4、16:9、9:16、21:9，并保持实测尺寸原样提交；`gpt-image-2-1k` 继续使用原有尺寸范围。
- Gemini 图片和 Chat 生图模型使用各自参考图字段与结果结构。
- Omni 支持单图、多图、V2V、双视频和相对下载地址，参考图优先保留公网链接并校验本地图片 8MB 限制，源站拒绝抓取时会提示重新上传；新版 Doubao/official Seedance 2.0 支持 4～15 秒和多类参考素材，Seedance 2.5 支持视频编辑。
- Doubao Seedance 2.0 同时使用单张参考图与参考视频或音频时，图片会作为普通参考素材提交，避免被误判为首帧并触发模式冲突；仅使用单张图片时仍保持图生视频模式。
- Doubao Seedance 2.0 mini/标准 480p 会在视频工作台、画布生成和重试入口统一检查参考视频尺寸；短边超过 480px 时直接提示并停止提交，不创建生成任务，也不请求接口。画布配置节点显示两行浅红警告并禁用生成，重试拦截只显示顶部错误提示，不覆盖原节点。远程视频无法取得尺寸时保留接口错误翻译兜底。
- AIHub 视频返回需要鉴权的相对地址时，会改用任务 ID 下载结果并保存到浏览器本地，避免直接播放临时地址失败。
- 本地 AIHub 异步图片重试拿到结果后会立即写入画布并结束计时；远程图片任务完成但没有返回图片时会明确失败，不再无限加载。
- AIHub 视频生成完成后会立即切换为“正在获取视频”；结果下载优先使用公开任务编号，失败时自动尝试返回地址中的结果编号，避免界面停留在旧进度且不会重复提交计费任务。
- AIHub 视频会保存首次提交得到的公开任务编号，后续状态响应不能用上游内部编号覆盖；画布恢复时也不会用内部编号代替公开编号查询，结果下载超时会自动切换备用编号，任务编号确实无效才结束转圈并明确提示。
- 视频内容策略拒绝会按错误来源显示中文提示：明确指向参考图时说明图片触发安全策略，来源不明确时提示更换素材或调整提示词。
- 视频进度只在 AIHub 返回有效百分比时展示；排队或生成阶段持续返回 `0` 时显示状态文字而不是错误的 0%，任务完成后固定显示 100%。
- `gemini-music` 使用 Chat Completions 生成音乐，并支持画布音频任务识别返回的音频地址。
- 旧 AIHub 默认模型列表会自动更新；已有自定义渠道及自行维护的模型列表保持不变。
- AIHub 模型配置支持 JSON 导入、导出和恢复内置配置；导入后模型目录、能力参数和适配器立即生效，配置文件不保存密钥。
- 图片、视频和音乐设置会按所选 AIHub 模型只显示有效参数；固定分辨率、固定时长等能力改为只读摘要。
- Omni 视频画幅设置使用等宽双列选项，明确显示横屏 16:9 与竖屏 9:16，固定输出规格改为弱提示。
- 图片与视频工作台、底部快捷栏、画布节点及工作流共用同一份模型能力库，切换模型时自动修正旧参数并收紧参考素材入口。
- 画布生成配置节点会按当前视频模型标记不兼容素材，`omni-fast` 只接受图片，`omni-fast-v2v` 实验性支持可选 1 张图片与必需 1～2 个视频同时输入；错误引用不会被静默删除，但会禁用生成并说明原因。
- 请求发出前会再次校验生成数量、画幅、时长、参考素材数量和文件大小，避免浏览器旧缓存发送无效字段。
- Grok 视频提示词超过当前约 4096 字符的参考值时，无限画布和视频创作台会在首次生成及重试前提示；用户可返回修改，也可继续提交，不会被客户端硬性拦截。
- Grok 6 秒视频固定输出 6 秒/480p，支持文生视频和最多 7 张参考图，不发送无效的时长或清晰度字段；Grok Lite 图片模型仅开放文生图能力。
- MiniMax-H3 五个模型已按 AIHub 原生协议接入：支持各自固定清晰度、4/5～15 秒、画幅、最多 5 张参考图、最多 3 个参考音频和成对首尾帧；Pro 模型另支持 1 个 2～5 秒参考视频。
- 已增加模型能力库、在线配置与可读文档的一致性检查；已下架的旧 Seedance、Grok 1.5、Veo-Clean 和旧文本模型不再预置。

## macOS 开发预览

- `Mac用户` 文件夹新增不依赖 Docker 的开发预览启动与停止入口，可直接运行当前源码并打开 `http://localhost:3000`。
- 启动终端会显示 `infinite-canvas画布` 运行横幅；Apple Terminal 使用原生双倍宽高标题，其他终端自动回退为普通醒目标题。
- 保持启动终端打开即可持续运行，关闭窗口会自动停止本次启动的前后端进程并清理 PID 记录；重复启动仍会直接打开现有页面。
- 停止入口只结束自身启动的前后端进程，端口冲突和启动失败会给出明确提示与日志位置。
- 原有 macOS Docker 双击入口保留为明确命名的备用方案，避免与原生安装包和开发预览混淆。

## Docker 双击启动（备用）

- Windows 和 macOS 均提供“启动或打开”和“停止”双击入口。
- 启动时自动检查 Docker Desktop、创建本地环境配置，并从 `3001`～`3099` 自动选择可用端口。
- 新手入口直接下载 GitHub 上预先构建的多架构成品镜像，不再在用户电脑上下载开发环境并编译项目。
- 镜像下载支持自动重试；电脑中已有镜像时可在网络异常时继续启动，失败信息会保存到 `data/launcher-logs`。
- 服务已运行时重复双击会直接打开现有页面；停止服务不会删除数据库、画布或素材。

## 免 Docker 原生安装包

- Windows x64 安装包内置前端、Go 后端和 Node.js 运行时，安装后只保留一个主入口，并通过系统托盘管理服务。
- macOS Apple Silicon DMG 只包含“AI创作工作台”一个应用，启动后常驻系统顶部菜单栏。
- 菜单栏和系统托盘提供“打开工作台”“重启服务”“退出并停止服务”；关闭浏览器页面不会停止服务。
- 桌面应用和网页标签使用深色画布图标；原用户可见停止入口已移除，卸载和自动测试仍可调用底层停止命令。
- 原生启动器首次选择网页端口后会永久沿用，升级时可继承正在运行的旧版端口；端口被占用时明确停止，不会静默换地址。
- 数据、日志和启动状态保存在系统用户目录，停止、升级或普通卸载不会删除。
- 浏览器本地画布、素材、生成记录、媒体文件和配置会按应用版本流式备份到独立用户目录；恢复只补充缺失项，内容冲突时保留恢复副本，不覆盖当前数据。
- GitHub Actions 会在 Windows 与 Apple Silicon macOS 运行器上验证首次启动、重复启动、健康状态、停止和 SQLite 创建，tag 构建自动上传 GitHub Release。
- 新版检测到旧版服务仍在运行时不会自动停止；用户可选择稍后继续使用旧版，确认没有生成中任务后再重启升级。升级沿用原数据目录，菜单栏和系统托盘的手动重启也会提前警告生成任务可能中断。
- macOS 安装包不再由系统阻止同一应用的再次打开，避免后台网页进程被误判为主应用后出现“没有响应”；启动器继续通过自身状态和进程锁防止重复启动服务。
