# 仓库同步说明

## 仓库关系

- 上游仓库：<https://github.com/tigerowo/infinite-canvas>
- 自有 Fork：<https://github.com/waynehaha/infinite-canvas>
- 旧 Fork 备份：<https://github.com/waynehaha/basketikun-infinite-canvas-backup>

本项目以 `tigerowo/infinite-canvas` 为上游来源，在 `waynehaha/infinite-canvas` 中保存自己的代码和提交。旧仓库原本 Fork 自 `basketikun/infinite-canvas`，因其与当前上游的 Git 历史不一致，已改名保留为备份。

## 本地远程配置

```text
origin    https://github.com/waynehaha/infinite-canvas.git
upstream  https://github.com/tigerowo/infinite-canvas.git
```

- `origin` 用于上传自己的代码。
- `upstream` 用于获取原作者的更新。

## 同步上游更新

同步前先确认工作区改动已妥善保存，再执行：

```bash
git fetch upstream
git switch main
git merge --ff-only upstream/main
git push origin main
```

`--ff-only` 会在本地主分支已经产生独立提交时停止，避免自动生成不明确的合并记录。遇到这种情况时，应先检查双方改动，再决定合并或变基，不要直接强制推送。

## 上传自己的改动

完成本地提交后执行：

```bash
git push origin main
```

如使用功能分支，将 `main` 替换为对应分支名，并在自己的仓库中创建 Pull Request。
