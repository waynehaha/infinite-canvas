# 免 Docker 桌面安装包方案

## 目标

让不熟悉开发环境的用户通过常规安装包使用无限画布，不需要预先安装 Docker、Go、Bun 或 Node.js。

目标体验：

```text
下载安装包 → 完成系统安装 → 点击无限画布 → 自动打开网页
```

第一阶段仍保留浏览器作为界面载体，不立即把整个项目重构为 Tauri 或 Electron 桌面应用。

## 推荐技术路线

安装包内包含完整运行环境：

```text
无限画布安装包
├─ Next.js standalone 前端产物
├─ Go 后端可执行文件
├─ 精简 Node.js 运行环境
├─ 启动器
└─ 数据目录与卸载信息
```

启动器负责：

- 启动前端和后端进程；
- 自动寻找可用端口；
- 等待健康检查通过；
- 打开系统默认浏览器；
- 防止重复启动；
- 在退出、重启和异常时清理子进程；
- 保存用户数据，升级或卸载时不误删。

## 目标平台

| 平台 | 第一优先级 | 后续扩展 |
| --- | --- | --- |
| Windows | x64 安装包 | ARM64 |
| macOS | Apple Silicon 安装包 | Intel |

Windows 可优先使用 Inno Setup 或 WiX 生成安装程序；macOS 使用 `.app` + `.dmg`。构建产物由 GitHub Actions 分平台生成，避免依赖开发者本机手动打包。

## 实施阶段

### 阶段一：无签名原型

- 完成 Windows x64 和 macOS Apple Silicon 构建；
- 验证首次安装、启动、端口冲突、退出、重启和数据保留；
- 验证 AIHub 默认渠道、图片生成和视频任务基础链路；
- 暂不提供自动升级。

### 阶段二：正式安装包

- Windows 增加代码签名并处理 SmartScreen 信任；
- macOS 增加开发者签名、公证和 Gatekeeper 验证；
- 增加开始菜单、桌面图标、卸载入口和版本信息；
- 明确应用数据目录及升级保留策略。

### 阶段三：发布和更新

- GitHub Release 自动生成各平台产物与校验值；
- 增加应用内版本检查或轻量自动更新；
- 提供崩溃日志导出和一键诊断；
- 评估是否需要迁移到 Tauri 或 Electron 获得托盘、窗口和更新能力。

## 主要难点

1. **代码签名和系统信任**：无签名程序会触发 Windows SmartScreen 或 macOS Gatekeeper，不适合作为面向新手的正式交付。
2. **多架构构建**：Go、Node.js 和 Next.js 产物需要按操作系统和 CPU 架构组合打包。
3. **进程生命周期**：启动器要可靠管理前后端进程，避免关闭页面后遗留后台进程。
4. **数据与升级**：数据库、素材和本地配置不能放在应用安装目录中，升级与卸载需要分别处理。
5. **体积和安全**：需要控制 Node.js 与静态资源体积，并验证安装包和依赖来源。

## 验收标准

- 全新电脑无需 Docker 或开发环境即可安装；
- 首次启动能自动打开正确页面；
- 端口冲突时无需用户处理；
- 重复点击不会启动多个实例；
- 退出后不残留前后端进程；
- 升级后用户数据库、画布和素材保持不变；
- Windows 和 macOS 默认安全流程中不出现无法解释的拦截；
- 安装、启动、停止、卸载均有简单中文提示。

## 当前决策

当前版本先交付 Docker 双击启动 MVP，验证用户是否确实需要本地安装包。免 Docker 方案保留为后续正式产品化路线，不在当前版本实施。
